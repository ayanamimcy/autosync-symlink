# 设计说明

项目由目录监控、全量对账、链接生成、元数据复制、清理和媒体库通知组成，各模块通过任务队列及持久状态协作。

数据保护策略：未知目标冲突不覆盖；目录删除事件先触发对账；使用持久清单、原子替换和持久通知队列。视频不做内容哈希。

流程：监听先启动 → 首次全量 → 缓冲事件补扫 → 定期对账。每个成功扫描都写 SQLite，重启时把未完成扫描标为 interrupted，并重新全量。目录扫描不完整时允许创建/更新可读文件，但禁止整个快照的清理。

平台监听由 `bridge/watch.py` 选择。Linux 通过 ctypes 调用 inotify，macOS 使用轮询，Windows 使用 ReadDirectoryChangesW。Linux 队列溢出、目录移动、自删除或卸载都会请求全量并重建监听；新目录递归添加 watch。inotify 默认递归监听数量与目录数相关，宿主机须按实际规模配置内核限制。

源健康标记校验媒体库身份。可选的 source/output mount_root 读取当前进程的 mountinfo，确认准确挂载点存在，并在扫描写入及清理前核对挂载身份未变。它不能消除所有挂载竞态，也不能证明云端返回的目录列表必然完整；未知或异常状态均保守停止处理。

已有源文件 signature 为大小、mtime_ns 和生成模式。元数据到验证周期后额外读取并计算内容哈希，避免同大小同时间变化漏检。输出内容哈希用于保护用户编辑，源变更不能自动覆盖已编辑的输出。复制前后检查源大小和时间一致，使用同目录临时文件及原子替换。

配置默认停用所有媒体库及外部 API，自动清理关闭。启用清理后仍须源健康、完整快照、缺失两次、宽限期、删除比例保护、输出指纹一致。手动清理是明确请求，但不会绕过这些保护。

全量完成由每库 `scan.last_full_success` 表示；局部扫描不更新这个时间。失败、延迟稳定、冲突和不完整快照不会被记录成全量成功。进程健康和数据就绪分开展示。

每库运行中的进度独立保存于内存：阶段、发现数、处理数、计划总数、变更、问题及当前路径。发现数在目录枚举时更新；文件完成数由各工作线程报告，不等待队列中较早的慢文件。发布快照使用锁，防止并发计数丢失。状态 API 将快照绑定到具体 scan id，界面只把它用于同一次正在运行的扫描。

扫描计数约每秒及阶段切换时检查点写入 SQLite，完成/失败时保存最终或部分计数，避免运行期间一直显示 0，也避免每文件额外写数据库。失败和清理不会把部分进度误记成首次全量成功。超限元数据的警告保留实际大小和配置上限；这类待处理项仍阻止全量成功标记。

Portainer 只管理容器生命周期，同步服务直接与本地 CloudDrive 及媒体服务器通信，不依赖 Oracle 管理面在线。每个媒体容器同时挂载源和链接输出，并保持一致的绝对路径。Docker 源挂载是只读；转存若要写源需单独规划授权挂载，不能直接开启示例中的只读源转存。

线程模型按库串行调度，每库内部有两个独立的并发阶段：`scan_workers` 控制目录枚举，`file_workers` 控制链接、STRM 和元数据处理。默认各 4，范围 1–32，1 为串行；旧配置加载时补齐默认值。完整快照及目标名/父子路径冲突校验完成后才开始文件写入。

线程池最多排入线程数两倍的任务，避免为整个媒体库创建 Future。目录阶段完成后释放枚举线程池，再启动文件线程池。文件任务返回独立结果，由协调线程按计划顺序统计；创建共用父目录使用互斥锁，SQLite 文件清单和通知事务继续通过 State 的锁串行提交。每次扫描日志包含总耗时和线程设置。

发生致命异常或服务停止时，取消未运行任务，正在读取的任务在下一检查点停止写入，清除临时文件，等待线程池结束后才返回错误；挂载变更会停止整次扫描并禁止清理。单文件 I/O 失败仍独立记录并允许其他文件完成。所有创建/更新任务结束后，清理和空目录裁剪再串行执行，不与文件写入并发。

远程文件系统正在执行的阻塞 I/O 无法保证即时取消；较高文件并发会增加同时读取元数据的内存和云盘请求压力。目录轮询监控本身仍为每库单线程。未实现复杂智能重命名和跨云移动。
